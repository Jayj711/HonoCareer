# 开发顺序

完全按接口文档 `AI面试与答辩模拟Agent-接口-yapi.json` 实现，共 48 个接口、9 个分类。按依赖关系分 10 个阶段，每阶段结束可独立验收。

## 全局约定（阶段 0 先定死，之后不再改）

- **统一响应包裹 `R`**：所有非 SSE 接口返回 `{ code, message, data, requestId }`，`code=0` 表示成功。
- **鉴权**：请求头 `Authorization: Bearer {accessToken}`；`/auth/refresh` 用 `refreshToken` 换新令牌。
- **幂等**：创建会话用 `Idempotency-Key` 头 + `clientSessionId`；发消息用 `clientMessageId`（重试不得重复推进阶段）。
- **流式模型（两段式）**：`POST /messages` 立即返回 `{ userMessageId, responseId, status }`，随后客户端另开 SSE 订阅 `GET /responses/{responseId}/events`，事件带 `eventId`，支持 `Last-Event-ID` 续传。

### 枚举值（以文档为准）

| 枚举 | 取值 |
|---|---|
| SessionMode | `interview` / `defense` |
| Scene | 面试 `employment`/`volunteer`/`club`；答辩 `thesis`/`research`/`course` |
| Modality | `text` / `voice` |
| SessionStatus | `active` / `generating_report` / `completed` / `failed` / `cancelled` |
| MessageKind | `answer` / `presentation` / `question` / `feedback` |
| MessageSendStatus | `queued` / `thinking` / `generating` / `completed` / `failed` |
| SSEEventType | `queued` / `thinking` / `tool_started` / `tool_finished` / `stage_changed` / `message_delta` / `message_completed` / `report_ready` / `error` / `done` |
| ProfileType | `employment` / `volunteer` / `club` / `defense`（defense 与前三种面试画像互不复用） |
| ClientType | `harmonyos` / `android` / `ios`（文档标注待确认：是否补 `web`/`miniapp`） |

## 阶段 0 — 数据模型 + DB + 统一响应

**范围**：`db/models.py`、`db/session.py`、`schemas/common.py`（`R` 包裹与分页）、`config.py`（已就绪）。

- 一次定义全部表：`User`、`Profile`（含版本号）、`Resume`、`DefenseMaterial`、`Session`、`Message`、`ResponseEvent`、`Report`、`WeakPoint`、`Memory`、`MemorySettings`。
- `R` 响应包裹、错误码约定、`requestId` 注入（中间件/依赖）。

**依赖**：无。
**验收**：`create_all` 建表成功；任意接口骨架返回标准 `R` 结构；`/health` 走通。
**理由**：模型与响应包裹是全局公共依赖，晚拆必返工。

| GET | `/api/v1/sessions/{sessionId}/responses/{responseId}/events` | 订阅 AI 响应流式事件（SSE） |

**验收**：发消息（`MessageSendDTO`：`clientMessageId/kind/content/inputMode/audioId?`）→ 拿 `responseId` → 订阅 SSE 依次收 `queued → thinking → stage_changed → message_delta* → message_completed → done`；阶段按 `InterviewStage`/`DefenseStage` 推进；状态机落库支持断点续跑。
**说明**：把当前 `/chat` 原型重构成文档的两段式真实模型，`InterviewState` 从内存态改为入库（`save/load`）。

## 依赖图（速览）

```
阶段0(模型/响应) → 阶段1(鉴权)
                    ├→ 阶段2(画像) ──┐
                    ├→ 阶段3(简历) ──┤
                    ├→ 阶段4(材料) ──┼→ 阶段5(会话) → 阶段6(消息+Agent) → 阶段7(报告/弱项)
                    ├→ 阶段8(记忆) ──┘
                    └→ 阶段9(语音)
```

- 阶段 2/3/4 三者可并行。
- 阶段 6 是核心闭环，阶段 7 依赖它。
- 阶段 8、9 相对独立，可穿插。
